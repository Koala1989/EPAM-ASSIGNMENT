# Findings

Mismatches between the InvenTree docs, the assignment brief and the actual behaviour of InvenTree 1.5.6, plus suspected product bugs.

| ID | Area | The source says | The app does | Evidence | Effect on tests |
|---|---|---|---|---|---|

UI-Part-004 changed. Doc issue 13. |
| F-02 | Part | Docs: Purchaseable shows supplier options, and an *Add Supplier Data* option enables supplier and manufacturer fields ([part-create.md#L47-51](../requirements/docs/part-create.md#L47-L51)). | No *Add Supplier Data* option. | F-09 | LST (API) | Schema: `GET /api/part/` and `GET /api/part/category/` return a paginated `{count, next, previous, results}` ([openapi-parts.yaml#L432](../requirements/openapi-parts.yaml#L432), [openapi-parts.yaml#L848](../requirements/openapi-parts.yaml#L848)). | Unless `limit` is sent, both return a plain JSON array of every record (441 parts, 28 categories on the demo data), also when only `offset` is sent. | F-11 | CRUD, VAL (API) | Schema: `Part.category_name` is a required read-only string ([openapi-parts.yaml#L4125](../requirements/openapi-parts.yaml#L4125), required at [openapi-parts.yaml#L4367](../requirements/openapi-parts.yaml#L4367)). | For a part with no category, every `Part` response (`POST`, `GET`, `PATCH`, bulk `items`) omits the `category_name` key altogether (not `null`, not `""`).
