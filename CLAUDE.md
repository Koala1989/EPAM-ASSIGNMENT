# EPAM Quality Architect assignment: InvenTree Parts

AI-assisted QA of InvenTree's **Parts module only**: manual UI and API test cases generated from requirements, then Playwright + TypeScript automation for both UI and API. Agents do the heavy lifting; the architect (the user) directs, reviews and approves.

## Application under test

- **InvenTree 1.5.6 (API 530)**, local Docker. Never upgrade it, and never compare against another version's docs.
- The address, timeouts and user credentials come only from `automation/shared/config/env.ts`, shared by the UI and API suites (each project's `config/env.ts` re-exports it). `TEST_ENV` (default `local`) selects `automation/shared/environments/<env>.json` and its users file `automation/shared/data/users.<env>.json`; passwords and overrides go in the gitignored `automation/shared/.env.<env>` (template `.env.example`) or real environment variables.
- Never run tests or create data on demo.inventree.org.
- Test records use a `QA-` name prefix and are cleaned up. Never delete records you did not create.

## Layout

| Path | Contents |
|---|---|
| `requirements/docs/` | Docs snapshot pinned to 1.5.6 (read-only). `INDEX.md`: heading index. |
| `requirements/openapi-parts.yaml` | Parts slice of the 1.5.6 OpenAPI schema (generated by `tools/slice_schema.py`; do not edit). Source for API rules. |
| `requirements/.rag-index/` | Local vector index over the docs (gitignored, rebuildable). |
| `test-cases/requirements-inventory.md`, `test-cases/<Area>/requirements-inventory.md` (API Areas: `test-cases/API_<Area>/`) | Reviewed, rule-ID'd requirements (`R-<Area>-NN`). Built by a full read of the docs, not by RAG. |
| `test-cases/<Area>/*.md` | Manual cases (`UI-<Area>-NNN`, `API-<Area>-NNN`), one folder per Area; API folders are prefixed `API_` (`test-cases/API_CRUD/`). IDs and the Area value are not prefixed. |
| `test-cases/<Area>/open-questions.md` (API: `API_<Area>`), `test-cases/findings.md` | Questions for the architect; app/doc mismatches found. |
| `references/seed-manual-test-case.md`, `references/seed-api-test-case.md` | The manual case formats: UI, and the API variant with the API Areas (`CRUD`, `LST`, `VAL`, `REL`, `SEC`). |
| `automation/shared/` | Configuration shared by both suites: `config/env.ts`, `environments/<env>.json`, `data/users.<env>.json`, `.env.example`. |
| `automation/ui/` | Playwright + TypeScript UI framework. Rules: `automation/ui/CONVENTIONS.md`. |
| `automation/api/` | Playwright + TypeScript API framework (clients, Ajv schema checks against `requirements/openapi-parts.yaml`). Rules: `automation/api/CONVENTIONS.md`. |
| `tools/` | `dedupe_cases.py` (duplicate check), `slice_schema.py` (schema slice), `rag/` (index build and query), `llm/` (prompt-caching demo). |
| `.claude/agents/`, `.claude/skills/` | Agents and skills. Submission copies: `agents/configs/`. |

## Agents and skills

| Step | Use |
|---|---|
| Manual cases | `/gen-test-cases <UI\|API> <functionality>`: test-case-creator, then duplicate-judge |
| UI automation | `/automate-cases <UI case ID> ...`: playwright-test-generator, healer, 3-run check, playwright-test-reviewer |
| API automation | `/automate-api-cases <API case ID> ...`: api-test-generator (writes, runs and stabilises), 3-run check, api-test-reviewer |

Every way to trigger a skill or an individual agent (slash command, headless CLI, plain language, @-mention): `agents/RUNNING.md`.

Keep reviewers and judges independent: pass them IDs or paths only, never another agent's reasoning or report. After editing any file in `.claude/agents/` or `.claude/skills/`, copy it to `agents/configs/` (same relative path) and check the copies match.

## Hard rules

- **Never assume a requirement.** Anything the docs and inventory do not state becomes an open question. Cases are still written, marked `Draft · Open question: Q-<Area>-NN`.
- **The architect owns approval.** Only the user sets a case's Review field to Approved, Changed or Rejected, edits requirements inventories, or answers open questions.
- **Never delete or rewrite saved test cases** unless the user asks.
- **Only Approved or Changed cases are automated.**
- **An app/case mismatch is a finding, not a fix.** Never weaken an assertion to make a test pass: mark it `test.fixme()` with a `// FINDING:` or `// CASE DEFECT:` comment and report it.
- **No hard-coded URLs, hosts, ports or credentials** anywhere outside `automation/shared/` (config, environments, users), including agent files.
- **UI tests log in through the real login form**, never with saved sessions or cookies.

## Commands

| Task | Command (from repo root unless noted) |
|---|---|
| Duplicate check | `python tools/dedupe_cases.py --case <ID> ...` |
| Rebuild schema slice | `tools/rag/.venv/Scripts/python.exe tools/slice_schema.py` (InvenTree running) |
| Build RAG index | `tools/rag/.venv/Scripts/python.exe tools/rag/build_index.py` (after any change to `requirements/docs/`) |
| Query RAG index | `tools/rag/.venv/Scripts/python.exe tools/rag/query_index.py "<question>" --top-k 3` |
| Lint / types / tests | from `automation/ui/` or `automation/api/`: `npm run lint`, `npm run typecheck`, `npx playwright test <spec>` |
| Another environment | `$env:TEST_ENV='<env>'; npm test` (PowerShell), with `automation/shared/environments/<env>.json` and its users and `.env` files in place |
| Stability check | `npx playwright test <spec> --project=chromium --repeat-each=3` (UI) or `--project=api` (API) |
